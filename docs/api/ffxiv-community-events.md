# FFXIV 活动日历数据契约

## 读取路径

网页读取规则：

1. 未配置 `VITE_FFXIV_COMMUNITY_EVENTS_URL` 时，直接读取 `/data/ffxiv/community-events.json`。
2. 已配置该变量时，优先读取配置的公开只读地址；读取或校验失败时回退到 `/data/ffxiv/community-events.json`。

所有数据地址都只允许公开 `GET`。网页不提供写入能力，也不持有机器人或存储服务凭据。

## JSON 格式

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-07-24T00:00:00+08:00",
  "events": [
    {
      "id": "fanfest-berlin-2026",
      "title": "FANFEST 2026 in 柏林",
      "url": "https://example.com/event",
      "startsAt": "2026-09-01T10:00:00+02:00",
      "endsAt": "2026-09-02T20:00:00+02:00",
      "timezone": "Europe/Berlin",
      "region": "global"
    }
  ]
}
```

字段约束：

| 字段            | 必填 | 约束                                                    |
| --------------- | ---- | ------------------------------------------------------- |
| `schemaVersion` | 是   | 当前必须为 `1`                                          |
| `updatedAt`     | 是   | 无活动时可为 `null`；发布器写入时使用带时区的 ISO 时间  |
| `events`        | 是   | 数组，最多 100 项                                       |
| `id`            | 是   | 唯一；小写字母、数字和连字符，最长 64 字符              |
| `title`         | 是   | 1 至 120 字符；Vue 按纯文本渲染                         |
| `url`           | 是   | 仅允许绝对 `http` 或 `https` 链接，最长 2048 字符       |
| `startsAt`      | 是   | 必须带 `Z` 或 `+08:00` 形式的时区                       |
| `endsAt`        | 否   | 必须晚于 `startsAt`，并带明确时区                       |
| `timezone`      | 否   | 最长 64 字符的展示/维护备注，例如 `Asia/Shanghai`       |
| `region`        | 否   | 允许 `common`、`cn` 或 `global`；兼容旧数据，省略时按 `cn` 展示 |

## 展示方式

- 共同活动、国服专属和国际服专属共用一条时间轴，并按该顺序由上到下分组，不拆成多个日历。
- 时间轴默认从当天 00:00 开始，让今天尽量靠近左侧；桌面向后显示约 35 天并逐日标注，移动端向后显示一个月并每 3 天标注。用户可无限向前或向后横向拖动；缩放后的单次可视跨度限制在 14 至 62 天。
- `startsAt` 和 `endsAt` 决定活动条的起止位置；省略 `endsAt` 时按开始时间后 24 小时显示。
- 一天活动保持真实窄条宽度，名称和结束时间移到横条旁显示，不通过缩小字号塞入横条。
- 时间轴加载 JSON 中的全部活动；已结束活动也保留，用户平移到对应日期时可见。实际能浏览到的活动历史与未来安排取决于 JSON 内容。
- 空数据、加载中和读取失败都有可见状态，日历本身不消失。

## 外部同步边界

- 网页只读取我们自己的 JSON，不在浏览器运行时请求灰机 Wiki 或其他第三方页面。
- 灰机 Wiki 等公开资料只能作为机器人或离线同步任务的输入；同步结果必须转换并校验为本文契约后再原子发布。
- 外部来源请求失败、被限流、被风控或解析结构变化时，发布器必须保留上一份有效 JSON，不得用空数组覆盖线上数据。
- 未取得稳定、可自动访问的数据接口前，不实现依赖页面 DOM 或 Cloudflare 挑战的脆弱抓取。

## QQ 机器人边界

机器人实现必须保留在 `NightingaleOpsBot`，不得复制到 V2：

1. 活动写命令只允许私有配置中唯一的站点所有者 QQ 号执行。
2. 群管理员、机器人管理员、好友和其他账号不能继承此权限。
3. 机器人在发布前执行与本契约一致的字段校验，并向所有者返回区服、起止时间和链接预览确认。
4. 发布采用临时文件加原子替换，避免网页读到半份 JSON。
5. 写入位置必须位于网站发布目录之外，防止部署 `dist/` 时覆盖运行时数据。
6. 所有者 QQ 号、机器人凭据、COS 密钥或服务器路径凭据只保留在未跟踪配置或服务端 secret 中。

如果机器人和网站在同一服务器，优先由 Nginx `alias` 暴露持久化 JSON；如果不在同一服务器，则由机器人上传到已限制权限的对象存储，并通过 `VITE_FFXIV_COMMUNITY_EVENTS_URL` 指向公开只读地址。
