# Roadmap

这是 V2 唯一维护“还没做什么”的文档。`docs/ai/MODULES/` 只记录当前行为、契约和验证方式；历史迁移原因保留在专题文档或 Git 历史中，不再另建并行待办。

## 当前阶段

阶段：已迁入工具的体验收口、生产边界稳定和回归补齐。

当前公开产品结构：`#/` 是像素 OS 桌面入口；非首页使用紧凑 OS 标题栏；正文工具页使用简约工作台语言。首页桌面承担工具与页面导航，`#/ffxiv` 仅承载 FFXIV 时钟和社区活动。

## P0：发布与可用性

1. NSGlamour 生产切流与烟测。
   - 将生产 `/api/glamour/*` upstream 切到 V2 `8766`，保留旧 `8765` 观察与回滚窗口。
   - 验证健康检查、图标代理的 HD/HR1 回退、石之家与 Eorzea Collection 导入成功和失败分支。
   - 以真实样本完成六套模板预览、原尺寸 PNG 导出与移动端导入/编辑/导出流程。

2. 公开构建边界。
   - 每次发布运行 `npm run check:release`、生产预览和公开页面烟测。
   - 持续阻止本地资产、NSArmoire catalog、内部 Style Lab / Silence chunk 与私有样本进入产物。

3. 近期 UI 回归。
   - 为 NSGlamour 模板的图片选择器、最近图片和最近配置补浏览器交互回归，覆盖窄视口、滚动与画布边界。
   - 保持空装备槽不生成无效图标 URL，图标统一使用公开 CDN 的 HD 优先规则。

## P1：核心工具回归与数据维护

1. NSPlate。
   - 维护静态 manifest、COS 素材、Canvas、信息层和 PNG/JPG/分层 ZIP 的回归矩阵。
   - 确认字体授权、OpenType 特性和生产缓存策略；旧 NSPortable 继续仅作 legacy/dev fallback 与契约参考。
   - 将图层顺序便签中出框角色层的上下箭头替换为手动上下拖拽排序，并补桌面/触摸/键盘可达性回归。

2. NSGlamour 与物品卡片。
   - 继续用已确认旧项目样本验证装备顺序、染剂语义、模板坐标和导出结果。
   - 物品卡片维护链接/文本导入、装备编辑及单张 PNG、批量 ZIP、连续列表长图三种导出，不与幻化私有状态重新耦合。

3. 时尚品鉴与 FFXIV 数据。
   - 按周维护公开当前周切片、四语主题、名称索引和来源核验。
   - 派生 CSV 数据必须通过对应生成器与 checker 更新；不将全量游戏源数据直接打入前端。

4. FFXIV 时钟与活动页。
   - 韩服房屋周期在取得可核验的具体截止时刻证据前不实现；不得由维护时间推导周期锚点。
   - 评估补充游戏公共时间信息或活动筛选/折叠前，先确认实际使用价值与移动端信息密度。

4. NSArmoire。
   - V2 公网页仅维护教程与 Release 下载入口。
   - 完整工作台、Helper、catalog 和分析规则继续在 `NSArmoireButler` 独立仓库验证和发布。

## P2：内容与后续分类

1. Silence。
   - 补齐用户确认的角色资料、正式文案和已授权素材后，单独制定公开上线计划。
   - 在此之前维持内部构建边界，不公开路由或资产。

2. Content Studio / Blog。
   - 为 Content Studio 补实际浏览器回归；当前 `tests/content/browser/content-studio-draft.spec.mjs` 仍是测试场景骨架。
   - 内容编辑与公开 Blog 的发布链路继续保持内部编辑、静态公开读取的边界。

3. 长期平台能力。
   - 在已有回归基线的前提下，逐步完善 CDN、缓存、监控和回滚流程。
   - FFXIV 分类稳定后，再评估博客、创作信息或其他游戏分类的公开入口。

## 明确暂缓

- 为统一技术栈而合并无关后端。
- 无基线时重写 Canvas 坐标、字体、裁切或导出逻辑。
- 无明确收益和实测数据时引入新依赖或大型公共抽象。
- 在资料、文案和资产未完成前公开 Silence。
- 把历史迁移流水继续追加到模块状态文档。
