# Feature Specification: 博客与专题富内容编辑器

**Feature Branch**: `main`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "在 V2 中提供比 NGA 更顺手的所见即所得编辑器，至少覆盖 NGA 编辑器能实现的主要排版效果；文章以完整结构化原稿保存，可导出为 NGA BBCode，Markdown 仅保留基础导出能力。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 编写并恢复富内容草稿 (Priority: P1)

作为站点所有者，我可以在不接触标记代码的情况下编写长文，插入复杂表格、单图和多图布局，并在离开或意外刷新后继续编辑最近保存的草稿。

**Why this priority**: 顺畅、可靠的写作体验是整个功能的核心；没有稳定原稿，其余发布和导出能力都没有基础。

**Independent Test**: 创建一篇包含标题、列表、引用、表格、单图和三图画廊的草稿，刷新页面后重新打开，确认内容、顺序、格式和图片信息完整恢复。

**Acceptance Scenarios**:

1. **Given** 站点所有者进入空白写作页，**When** 输入正文并插入受支持的富内容块，**Then** 页面以所见即所得方式显示最终阅读结构，不要求手写 BBCode 或 Markdown。
2. **Given** 草稿已经自动保存，**When** 页面刷新、浏览器重启或再次打开该草稿，**Then** 最近一次成功保存的标题、正文结构和资源引用完整恢复。
3. **Given** 自动保存失败，**When** 所有者继续编辑，**Then** 页面明确显示未保存状态并保留当前编辑内容，不把失败误报为成功。

---

### User Story 2 - 预览并发布内容 (Priority: P1)

作为站点所有者，我可以创建统一的内容条目，填写必要元数据，在发布前查看真实阅读效果，并只把明确发布的版本展示给公开访客。博客文章和长篇专题首版共用同一内容模型；专题集合/章节关系留待独立需求。

**Why this priority**: 用户的目标是让 V2 承载博客和长篇专题内容，而不是只获得一个孤立编辑器。

**Independent Test**: 创建两篇内容，预览后发布其中一篇；博客列表和详情页只显示已发布内容，草稿不能通过公开入口读取。

**Acceptance Scenarios**:

1. **Given** 一篇有效草稿，**When** 所有者打开发布预览，**Then** 预览使用与公开阅读页一致的内容结构和主题表现。
2. **Given** 一篇仍为草稿的内容，**When** 公开访客访问列表、搜索结果或猜测详情地址，**Then** 草稿标题、正文和图片均不可见。
3. **Given** 所有者明确执行发布，**When** 发布成功，**Then** 内容获得稳定的公开地址并出现在博客入口。
4. **Given** 已发布内容被继续编辑，**When** 新修改尚未再次发布，**Then** 公开访客仍看到上一次成功发布的版本。

---

### User Story 3 - 导出 NGA BBCode (Priority: P2)

作为站点所有者，我可以把同一篇原稿导出成可粘贴到 NGA 编辑器的 BBCode，并在 V2 独有布局无法一比一表达时得到明确的降级说明。

**Why this priority**: 用户希望 V2 成为主要写作环境，同时保留向 NGA 发布同一内容的能力，不再忍受 NGA 原生编辑器的操作手感。

**Independent Test**: 将包含格式文本、引用、列表、链接、代码、表格、单图、多图和折叠块的样例导出，粘贴到 NGA 预览并核对正文、图片顺序、表格单元格和标题层级。

**Acceptance Scenarios**:

1. **Given** 原稿只包含 NGA 可直接表达的内容，**When** 导出 BBCode，**Then** 导出结果保留全部文字、链接、图片引用、表格内容和内容顺序。
2. **Given** 原稿包含 NGA 无法等价表达的画廊或专题块，**When** 导出 BBCode，**Then** 系统使用预定义的简化形式输出，并列出发生降级的内容块和原因。
3. **Given** 导出完成，**When** 所有者继续编辑 V2 原稿，**Then** 导出操作不会改写或降级原稿本身。

---

### User Story 4 - 基础 Markdown 导出 (Priority: P3)

作为站点所有者，我可以在需要备份或迁移时导出基础 Markdown；复杂布局可以简化，但正文和资源引用不能静默丢失。

**Why this priority**: Markdown 不是主要写作或发布格式，只承担轻量兼容和可迁移性保障。

**Independent Test**: 导出一篇混合内容样例，确认普通文本、标题、列表、引用、代码、链接和图片可读，复杂块均有内容或明确替代说明。

**Acceptance Scenarios**:

1. **Given** 一篇有效原稿，**When** 导出 Markdown，**Then** 基础文本结构按常见 Markdown 语义输出。
2. **Given** 原稿包含复杂表格、画廊或专题块，**When** 导出 Markdown，**Then** 系统进行可读降级或明确标注，不静默删除内容。

### Edge Cases

- 空标题、重复公开地址标识、超长标题或非法地址标识不能进入发布状态。
- 空正文允许保存为草稿，但不能发布。
- 粘贴来自网页或办公软件的内容时，不保留脚本、事件处理器、未知嵌入和不受支持的样式。
- 图片上传中断、格式伪装、尺寸超限或资源失效时，原稿必须保持可编辑，并指出具体失败资源。
- 表格为空、行列达到上限、合并区域冲突或删除最后一行/列时，编辑器必须保持有效文档结构。
- 自动保存与手动发布并发时，不能让较旧内容覆盖较新内容。
- 浏览器离线或发布服务不可用时，必须区分“本地草稿已保存”和“公开版本已发布”。
- BBCode 或 Markdown 导出遇到未知内容节点时，必须阻止无提示导出，或输出显式占位与损失报告。
- 已发布内容引用的图片不得因删除草稿或替换草稿图片而失效。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅向站点所有者开放创建、修改、删除、预览和发布能力；公开访客只能读取已发布内容。
- **FR-002**: 所有者 MUST 能创建统一的内容条目；首版不强制区分博客与专题类型，专题集合/章节关系留待独立需求。
- **FR-003**: 每篇内容 MUST 包含标题、公开地址标识、状态、正文、创建时间和更新时间，并可选填摘要、封面和标签。
- **FR-004**: 编辑器 MUST 支持段落、二至四级标题、粗体、斜体、下划线、删除线、文字颜色、离散字号、对齐、链接、行内代码、有序列表、无序列表、引用、代码块、分隔线和折叠内容。
- **FR-005**: 表格 MUST 支持新增和删除行列、表头、单元格对齐、调整列宽以及合并和拆分单元格，并阻止产生无效表格结构。
- **FR-006**: 图片内容 MUST 支持单图、替代文本、图注、对齐和可控显示尺寸。
- **FR-007**: 多图片内容 MUST 支持至少双列、三列和自适应网格布局，并保留图片顺序、替代文本和图注。
- **FR-008**: 编辑器 MUST 支持选择图片、粘贴图片和拖入图片；上传失败不得破坏正文或其他已成功资源。
- **FR-009**: 从剪贴板进入的富文本和外部内容 MUST 被规范化为受支持结构，不得保留可执行脚本、事件属性或未知嵌入。
- **FR-010**: 系统 MUST 自动保存草稿并显示保存中、已保存、未保存和保存失败状态。
- **FR-011**: 系统 MUST 在重新进入草稿时恢复最近一次成功保存的完整可编辑结构。
- **FR-012**: 系统 MUST 提供与公开阅读页语义一致的发布前预览。
- **FR-013**: 内容 MUST 支持 `草稿`、`已发布` 和 `已归档` 状态；只有明确发布的版本可被公开读取。
- **FR-014**: 已发布内容继续编辑时，系统 MUST 将未发布修改与当前公开版本隔离。
- **FR-015**: 公开入口 MUST 提供博客内容列表和稳定详情地址，并仅返回已发布内容。
- **FR-016**: 系统 MUST 使用带版本号的结构化原稿保存所有受支持内容语义，以便未来迁移并检测未知节点。
- **FR-017**: 系统 MUST 将 NGA BBCode 作为核心导出格式，覆盖全部基础文本格式、标题层级、引用、列表、链接、代码、表格、图片和折叠内容。
- **FR-018**: NGA BBCode 导出 MUST 对不可等价表达的 V2 内容应用确定性降级规则，并生成逐项损失报告。
- **FR-019**: NGA BBCode 导出 MUST 保留正文和图片顺序，不得修改原始草稿或公开版本。
- **FR-020**: 系统 MUST 提供基础 Markdown 导出；Markdown 不承担复杂表格、画廊和专题布局的一比一还原。
- **FR-021**: 任何导出遇到未知节点、无效资源或不受支持属性时，MUST 明确警告，不得静默丢弃。
- **FR-022**: 内容、元数据和图片输入 MUST 在保存与发布边界接受格式、大小、数量和结构校验。
- **FR-023**: 阅读页 MUST 安全渲染受支持内容，不能执行正文中携带的脚本、事件处理器或任意原始 HTML。
- **FR-024**: 发布、撤回、归档和资源变更 MUST 产生足以定位时间、内容和结果的所有者审计记录，且不得记录正文、凭据或敏感配置。
- **FR-025**: 所有固定编辑器、状态、错误、预览和发布界面文案 MUST 通过站点本地化机制读取。
- **FR-026**: 编辑器的核心命令 MUST 可通过键盘和可识别控件完成；仅图标控件必须具有可访问名称。

### Key Entities

- **ContentEntry**: 一篇统一内容条目的身份和元数据，包括公开地址标识、状态、摘要、封面、标签及时间信息；专题集合/章节关系不属于 v1。
- **ContentDocument**: 可编辑正文的版本化结构，包含有序内容节点、文本标记和节点属性。
- **ContentRevision**: 某篇内容的一次草稿或发布快照，用于隔离正在编辑的内容与公开版本。
- **MediaAsset**: 正文或封面引用的图片资源，包括资源身份、地址、尺寸、格式、替代文本、状态和引用关系。
- **ExportArtifact**: 从特定正文版本生成的 BBCode 或 Markdown 文本，以及格式、生成时间和降级报告。
- **ExportLoss**: 某个节点或属性无法被目标格式等价表达时的结构化说明，包括位置、原因和采用的降级规则。
- **AuditEvent**: 发布、撤回、归档及资源变更的最小审计记录，不保存正文或敏感信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有者可在 5 分钟内从空白页面完成一篇包含标题、表格和三图画廊的草稿并重新打开继续编辑，无需接触标记代码。
- **SC-002**: 对包含 50,000 个字符、50 张图片和一个 20×20 表格的验证样例，编辑、保存、重新加载和预览均能完成，且正文结构和资源顺序无丢失。
- **SC-003**: 自动保存成功后 2 秒内显示明确状态；模拟刷新或浏览器重启后可恢复最近一次成功保存的版本。
- **SC-004**: 受支持节点经过“保存、关闭、重新打开”往返后，验证样例中的节点类型、顺序、文本和关键属性保持 100% 一致。
- **SC-005**: NGA BBCode 黄金样例在 NGA 预览中保留 100% 的正文文本、链接目标、图片引用、图片顺序和表格单元格内容；所有布局降级均出现在损失报告中。
- **SC-006**: Markdown 导出的基础标题、段落、列表、引用、代码、链接和图片在验证样例中无静默丢失；复杂块均产生可读降级内容或明确警告。
- **SC-007**: 未发布、已撤回和已归档内容在公开列表及直接地址测试中均不可读取；已发布内容可通过稳定地址读取。
- **SC-008**: 恶意粘贴、伪装图片、未知节点和脚本属性验证样例均不能在编辑器预览或公开阅读页执行代码。
- **SC-009**: 公开阅读页在项目规定的桌面和移动视口中无横向溢出，长表格和多图片内容仍可阅读和操作。
- **SC-010**: 编辑器与阅读页新增的固定 UI 文案 100% 通过本地化 key 提供，并通过项目现有文案检查。

## Assumptions

- 第一版只有站点所有者一名作者，不提供注册、多人作者、协同编辑、评论、收藏或社区发帖功能。
- 第一版博客文章与长篇专题共用同一内容条目和 `/blog/:id` 详情路由；`id` 为服务器生成的数字公开标识，多文章专题集合另行设计。
- 第一版写作工作台以桌面端为主；公开阅读页必须完整支持桌面和移动端，移动端完整富内容写作不在首版范围。
- 所有者写作入口不会作为无保护的公开页面发布；具体采用内部构建还是受保护在线入口由技术计划决定。
- 结构化原稿是唯一完整事实来源；BBCode 和 Markdown 都是派生导出物，不能反向覆盖原稿。
- NGA 导出追求内容和主要排版可用，不要求 V2 与 NGA 像素级一致。
- Markdown 需求优先级较低，首版不包含 Markdown 导入和复杂 Markdown 扩展兼容。
- BBCode 导入、NGA 帖子同步、远程抓取和自动代发 NGA 均不在首版范围。
- 第一版不允许任意原始 HTML、任意脚本、iframe 或未知第三方嵌入；后续每种嵌入必须单独定义白名单契约。
- 图片只有在所有者明确发布内容后才进入公开资源边界；未授权本地预览资产不得进入构建产物或公开存储。
- 首版公开内容使用现有 V2 站点承载；搜索引擎预渲染和从 hash 路由迁移不作为本功能首版验收条件，但必须在计划风险中记录。
